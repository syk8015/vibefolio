# 설계안 — 주인 인터뷰 + 진짜 기록 모드 (2026-09-28)

> 상태: **설계안(구현 전)**. 사용자와 합의한 방향: "데모는 진짜 앱과 같지 않다 → 만든 사람의 의견과, 동의 아래 진짜 기록을 넣어 실제로 도는 앱처럼 보이게."
> 배경: 사용자의 개인 프로젝트 5개를 각 프로젝트 세션과 인터뷰한 결과(레포 밖 기록). 다섯 곳 모두 "화면만으로는 가치가 절반만 보인다"고 답했다.

## 0. 한 줄 요약

- **주인 인터뷰**: 올리는 AI가 초안을 쓰기 전에 주인에게 3~4가지를 묻고, 그 답이 촬영 강조점·자막·"만든 사람의 한마디"를 정한다. 주인은 공개 전에 "내 말이 맞다"를 확인해야 한다.
- **진짜 기록 모드**: 주인 컴퓨터에서 진짜 앱 상태를 한 번 떠 와서(저장 데이터 + 서버 응답과 그 박자), **주인 컴퓨터 안에서** 가리고, 주인이 미리보기로 확인한 뒤 비공개로 올린다. 로봇이 그걸 심어 찍고, 찍은 뒤 지운다. 영상엔 "만든 사람의 실제 사용 기록 · 이름 가림"을 붙인다.

---

## 1. 지금 흐름과 빈칸

지금: AI가 코드만 읽고 제목·설명·`demoScript`를 혼자 쓴다(`schema/publish.json`의 publishDescription: "You are the AI that built it, so write … yourself"). 주인은 초안 검토 창에서 글을 고치거나 단계를 빼고·순서만 바꾼다. `builderNote`(말풍선 한 줄)도 AI가 쓴다.

빈칸 두 개:
1. **주인의 판단이 안 들어간다.** 어디가 제일 중요한지, 실제로 어떻게 쓰는지는 만든 사람만 안다. AI는 코드에서 추측할 뿐이다.
2. **데모는 진짜와 다르다.** 가짜 데이터 체험 화면은 같은 화면을 보여줄 뿐, 진짜 기록("나를 안다"), 새 질문에 답하는 진짜 AI, 화면 밖 순간(폰 알림·센서·정해진 시각의 자동 작업)이 빠진다. 체험 모드를 만드는 데 코드 수백 줄이 들기도 한다.

## 2. 주인 인터뷰 (1단계 — 작음)

### 2.1 질문 (고정 3개 + 선택 1개)
AI가 채팅에서 주인에게 **그대로** 묻고, 답은 주인의 말로 옮긴다(지어내기 금지).

1. **제일 자랑하고 싶은 장면은?** — What's the moment you're proudest of?
2. **실제로 어떻게 쓰고 있어?** (언제·얼마나 자주·무엇 때문에) — How do you actually use it?
3. **처음 보는 사람이 꼭 봐야 할 것 하나는?** — One thing a first-time viewer must notice?
4. (선택) **보여주면 안 되는 것은?** (사람 이름·금액·장소·건강 정보 등) — Anything that must not be shown?

### 2.2 답이 쓰이는 곳
- 1·3 → `demoScript` 강조: 해당 단계의 hold를 늘리고, 첫 장면이나 마지막 장면에 둔다. `check`가 "강조 장면이 대본에 있는지"를 확인한다.
- 2 → 작품 페이지의 **"만든 사람의 한마디"**(2~3줄, 공개). `builderNote`(말풍선 한 줄)도 여기서 뽑는다.
- 4 → 가리기 규칙(§3.4)과 촬영 금지 목록. **공개 안 함**.
- 1~3 → 자막(영어 자막 기능이 생기면 그대로 재료).

### 2.3 데이터·게이트
- 페이로드: `ownerInterview: { proudMoment, howIUse, mustSee, hide?: string[] }` — 채팅 AI·CLI·원격 MCP 모두 같은 원본(`schema/publish.json`)에서.
- 게이트: `OWNER_INTERVIEW_REQUIRED` — 기존 게이트(대본 → 로그인 답 → targetDevice) 뒤. dry run(`nookframe check`)이 먼저 알려준다. 거절 문구는 "주인에게 이 3가지를 먼저 물어보세요"로 AI가 바로 행동하게.
- 칸: `projects.owner_interview` jsonb = **PRIVATE**(`hide` 목록이 들어 있음, AGENTS.md 규칙대로 `PRIVATE_PROJECT_COLUMNS`). `projects.maker_note` text = **PUBLIC**(주인 확인 뒤에만 채움, GRANT SQL 필요).
- 초안 검토 창: 오른쪽에 **"주인 인터뷰"** 칸 — 답 3개(고칠 수 있음) + 만든 사람의 한마디 미리보기 + 체크 "내 말이 맞아요". 이 체크가 없으면 [공개하기]가 안 눌린다. AI가 꾸며 쓴 답을 주인이 걸러내는 마지막 자리.
- 작품 페이지: 영상 아래 "만든 사람의 한마디" 칸(→ **목업 먼저**).

### 2.4 만들 것
`schema/publish.json`(+`npm run schema:build`) · `app/api/ingest/*` 게이트 · SQL 마이그레이션(칸 2개 + GRANT) · `DraftReviewModal` 칸 · 작품 페이지 칸 · Connect 프롬프트 문구 · 프로브(게이트·칸 공개 범위) · CLI 새 버전(사용자가 `npm publish`). 대략 1~2일.

## 3. 진짜 기록 모드 (2단계 — 큼)

### 3.1 원칙 (바꾸지 말 것)
1. **주인 컴퓨터 안에서 가린다.** 가리기 전의 진짜 기록은 Nookframe 서버에 오지 않는다.
2. **비밀값은 절대 안 받는다.** 로그인 쿠키·토큰·요청 헤더는 떠 오지 않는다. 09-01 결정(“남의 비밀값을 맡아 데모에 주입하지 않는다”, `lib/upload-safety.ts`)과 같은 선.
3. **주인이 본 것만 올라간다.** 가린 결과를 미리보기로 보고 동의해야 올라간다.
4. **찍고 지운다.** 떠 온 묶음은 비공개 저장소에만, 촬영 뒤(또는 14일 뒤) 삭제.
5. **정직하게 표시한다.** "만든 사람의 실제 사용 기록 · 이름 가림 · 9월 28일 녹화", 빨리감기면 "⏩ 3×".
6. **내 앱일 때만.** 앱 주소의 주인 확인(§3.6)이 끝나야 응답 재생을 허락한다 — 아니면 남의 사이트에 가짜 답을 넣어 그럴듯한 시연을 꾸밀 수 있다.

### 3.2 흐름
```
주인+AI (주인 컴퓨터)                         Nookframe                        촬영 로봇(맥)
─────────────────────────────                ─────────────                    ─────────────
1 nookframe capture <앱 주소>
  → 새 프로필 크롬 창이 열림
2 주인이 평소처럼 로그인·사용
  (폰에만 기록이 있는 앱은 앱 자체
   백업 파일을 먼저 불러옴)
3 [다 됐어요] → 떠내기:
  · 저장 데이터(localStorage·IndexedDB·사진)
  · 허용한 API 응답 + 조각 도착 시각
4 가리기(자동 + .env 대조 + 인터뷰 4번 목록
  + 바꿔치기 규칙) → 미리보기 HTML
5 주인 확인 "올려도 돼요" ──────────────→ 6 비공개 저장, 초안에 연결
                                            (주소 주인 확인 필요)
                                                                      7 공개 버튼 → 촬영:
                                                                        씨앗 심기 → 응답 재생
                                                                        (박자 유지·빈 구간 압축)
                                                                        → 글자 바꿔치기 2차 그물
                                                                        → 표시 라벨 → 녹화
                                            8 촬영 끝 → 묶음 삭제
```

### 3.3 무엇을 떠 오나
- **저장 데이터(씨앗)**: localStorage + IndexedDB(버전 포함) + 사진 같은 파일은 따로. 형식은 아래 `nookframeSeed`.
- **서버 응답(테이프)**: 같은 도메인 API 중 **로그인·비용·매번 다른 답**이 걸린 주소만(AI가 코드를 읽고 목록을 제안, 주인이 확인). 응답의 상태·타입·본문·**조각 도착 시각**만 저장. 요청 헤더·쿠키는 저장 안 함, 요청 본문은 해시만.
- **진짜로 받는 것**: HTML·JS·CSS·글꼴·이미지·공개 데이터 파일. 이걸 재생하면 옛 빌드가 굳어 "지금도 돈다"가 거짓이 된다.
- 로그인 응답(`/api/auth/session` 같은 것)은 녹화하지 않고 **합성**한다 — 인증 라이브러리별 프리셋(Auth.js · Supabase · Firebase · 직접 만든 것), 표시 이름은 가짜.

씨앗 형식(초안 — 스킨로그 세션 시험 결과를 반영):
```json
{
  "nookframeSeed": 1,
  "origin": "https://example.app",
  "localStorage": { "app.profile": { "$json": { "skinType": "combination" } } },
  "indexedDB": [{ "name": "app-db", "version": 3, "stores": [
    { "name": "items", "keyPath": "id", "records": [
      { "id": "a1", "name": "…", "createdAt": { "$now": "-2d" } } ] } ] }],
  "files": [{ "store": "photos", "key": "p1", "field": "blob", "$blob": { "type": "image/jpeg", "file": "p1.jpg" } }],
  "cookies": []
}
```
- `$now`: 날짜를 "촬영 시점 기준 며칠 전"으로 — 몇 달 뒤 찍어도 낡아 보이지 않게.
- `$json`: 문자열로 저장된 JSON을 AI가 이스케이프하다 틀리지 않게.
- `$blob`: Playwright 형식은 Blob을 빈 객체로 만든다(시험 확인) → 파일로 따로.
- DB `version`은 앱보다 높으면 안 된다(VersionError로 앱이 깨짐) → check가 "앱 3 · 씨앗 3 ✓".

### 3.4 가리기
순서대로, 전부 주인 컴퓨터에서:
1. **자동 패턴**: 이메일 · 전화번호 · 계좌·카드 번호 모양 · JWT · API 키 모양(`sk-`, `eyJ…`) · 긴 base64 · `token=` · IP · MAC · 비공개 호스트 주소(`*.vercel.app`, `*.supabase.co` 등 앱 자체 주소 제외).
2. **주인의 `.env` 값과 대조**: 값이 기록 어디에 있든 찾아서 가린다. `.env` 값 자체는 어디에도 안 보낸다.
3. **인터뷰 4번 목록 + 바꿔치기 규칙**: "엄마 → Family member", "○○방 → Bedroom 2", 금액은 "비율로" 또는 "₩•••"로. AI가 기록을 훑어 사람 이름으로 보이는 것을 후보로 제안.
4. **민감한 종류는 기본값이 "값 가림, 구조는 보임"**: 건강(병명·처방), 돈(금액·잔고), 집에 있는지 드러나는 시각(샤워·취침), 위치.
5. **미리보기**: 바뀐 곳은 초록, 아직 의심스러운 곳은 빨강으로 칠한 로컬 HTML. 주인이 빨강을 전부 처리해야 [올리기].
6. 서버에서 한 번 더 같은 검사(두 번째 그물). 촬영 때 화면 글자 바꿔치기(MutationObserver)로 세 번째 그물 — 화면에서 계산돼 나온 이름까지 잡는다.

### 3.5 다른 사람의 정보
- 주인 동의는 **주인 자신의 정보에만** 유효하다. 가족·연인·고객의 이름·메시지·기록이 보이면 가려야 한다.
- 떠내기 끝에 체크: "다른 사람의 정보는 없거나 모두 가렸어요". 사람 이름 후보가 남아 있으면 경고.

### 3.6 앱 주인 확인
- 방법(하나만 되면 됨): 앱에 `/.well-known/nookframe-verify.txt`(토큰 한 줄) · `<meta name="nookframe-verify" content="…">` · DNS TXT. `*.vercel.app` 같은 하위 주소도 앞의 둘은 된다.
- 확인 전엔 응답 재생을 못 쓰고, 씨앗 심기만 된다(씨앗은 방문자 화면을 바꾸지 않고 로봇 브라우저에만 들어가므로 위험이 작다).

### 3.7 촬영 쪽(로봇) 바뀌는 곳
- 지금 `local-runner/safety.ts`가 이미 `page.route('**/*')`로 **쓰기 요청을 가짜 200으로 막는다**(진짜 서버에 쓰기가 안 닿음). 응답 재생은 이 앞에 한 겹 더 얹는다: 허용 주소는 테이프에서, 테이프에 없는 같은 도메인 쓰기는 지금처럼 막고 "녹화 안 된 요청" 기록.
- 흐르는 답(SSE·스트리밍)은 `route.fulfill`로 주면 한 번에 떠 버린다(시험 확인) → `addInitScript`로 `fetch`를 감싸 **페이지 안 ReadableStream에 조각을 시간 맞춰** 넣는다. 연결 유지 줄(`: ping`)은 박자 계산에서 뺀다. 빈 구간은 1.2초로 자르고 글쓰기는 최대 3배속 → 라벨 "⏩ 3×".
- 씨앗: 녹화용 새 컨텍스트를 열 때 지금은 쿠키·localStorage만 넣는다(`launchRecordingContext(storageState)`) → IndexedDB·파일까지.
- 라벨: `postprocess`/`endcap` 단계에서 영상 한쪽에 작은 표시. 작품 페이지 영상 옆에도 같은 문구.
- 서버 쪽에서 쿠키로 페이지를 막는 앱(미들웨어·서버 렌더링에서 로그인 확인)은 이 방식으로 안 된다 → 떠내기 단계에서 알아채고 "주인 영상" 길로 안내.

### 3.8 저장·보존
- 새 비공개 버킷(예: `captures`) — 서비스롤만 읽기·쓰기. `project-files`는 공개 버킷이라 쓰면 안 된다.
- 표(예: `project_captures`): project_id · owner_id · kind(seed/tape) · storage_key · 가리기 보고서 · consent_at · domain_verified_at · expires_at · status. 전부 PRIVATE.
- 촬영이 끝나면 즉시, 안 찍히면 14일 뒤 삭제(헬스 크론에 얹기). 작품 삭제 때도 같이(`DELETE /api/projects/[id]/demo-assets`).

### 3.9 법·약관
- 개인정보처리방침에 "진짜 기록 모드"로 받은 자료의 처리 목적(촬영만)·보관 기간(촬영 뒤 삭제, 최대 14일)·접근 범위(촬영 로봇만)를 추가해야 한다. 건강·금융 기록이 섞일 수 있는 기능이라 **켜기 전에** 필요.
- 이용약관 6조(업로드 파일 처리)에 한 줄.

## 4. 브라우저 밖 순간 (3단계)
- 주인 폰 클립 이어 붙이기: 로봇 영상 앞뒤에 주인이 찍은 5~10초(폰 잠금화면 알림, 실물 기기). 라벨 "주인이 직접 찍음".
- 알림 재현: 테이프에 알림 내용이 있으면 폰 알림 모양 배너를 영상 위에(라벨 "재현").
- 가동 배지(하트비트)와 합치면: "진짜 기록으로 찍었고 · 지금도 돌고 있다".

## 6. 정해야 할 것
