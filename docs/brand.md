# Nookframe 브랜드 (한 권)

브랜드에 닿는 일(새 문구·로고·아이콘·영상·광고·공유 그림·촬영 효과)을 하기 전에 **먼저 읽는다.** 화면 하나하나의 모양·글 규칙은 `docs/ui-rules.md`가 맡고, 이 문서는 "우리가 누구로 보이는가"를 맡는다.
흩어져 있던 결정(기억 파일·광고 작업 폴더·코드 주석)을 2026-11-05에 여기 한 곳으로 모았다. 괄호 안은 정한 날짜. 바꾸려면 사용자가 정하고 이 문서를 같이 고친다.
**빈 칸(§11)은 아직 안 정한 것**이다 — 정해지기 전까지 새 영상·효과는 시안을 먼저 보여 주고 고른다.

## 1. 핵심 생각

- **정체성 (10-02):** 보이는 건 다 진짜다. 그리고 그 사실마다 누가·언제 확인했는지 적는다.
  - 출처 단계: 로봇이 확인 / 주인 기기 기록 / git / 주인이 말함. 모르는 건 회색이지 빨강이 아니다. 실패는 강등이지 삭제가 아니다. 주인은 멈추거나 숨길 수 있어도 기록을 고칠 수 없다.
  - 그 확인 기능이 나오기 전까지는 글에 "누가 언제 확인했는지"를 약속하지 않는다.
- **진짜와 연출의 경계 (11-06):** "모양은 연출해도 된다. 작품이 한 일은 손대지 않는다."
  - 연출해도 되는 것(포장): 카메라 움직임, 결과 장면 먼저 보여 주기(진짜 장면만), 주소 줄·끝 화면·소리, 화면 없는 작품의 장르 모양(영수증 등), 눅프레임 자기 이야기인 손그림 광고.
  - 손대지 않는 것(내용): 작품 화면의 색·질감, 속도(빨리 감기), 누르지 않은 결과 붙여 넣기, 숫자·날짜·확인 기록, 작품에 없는 기능·데이터 그려 넣기.
  - 긴 기다림(로딩 등)은 잘라 내도 되지만 자른 자리에 기다린 시간을 남긴다(예: `⋯ 8s`). 몰래 자르지 않는다.
  - 숫자·글은 진짜 값(코드·주인 확인·실측)이 원칙. 예외는 장면 구석에 "Sample data"를 단 예시 값뿐(소개 영상 `data: sample`, `docs/intro-film.md`) — 표시 없는 예시 값은 없다.
  - **바깥에 내거는 '안 하는 일' (11-06, 문구 그대로):** 붙일 곳(영상 아래 링크·보안 편 소개 작품)은 화면 시안 때 정한다.
    ```
    We film your app at real speed. Long waits are cut and marked.
    We never retouch what your app shows.
    Every result on screen came from a real click.
    Example numbers always say "Sample data".
    ```
    - "진짜 데이터에 저장하지 않는다"는 약속하지 않는다 — 촬영 중 쓰기 요청 가로채기(`local-runner/safety.ts`)는 막는 장치이지 보장이 아니다. 같은 까닭으로 "진짜로 저장됨"이 아니라 "진짜로 누름"까지만 말한다.
    - 줄을 더하거나 고칠 땐 지금 촬영 방식에서 이미 사실인지 먼저 확인한다.
- **한 줄 (09-24, SNS 소개):** `For what comes after you build it` — 다들 "만들어라"를 말할 때 우리는 **만든 다음**을 말한다.
- **철학:** "자랑이 아니라 흔적." / "어떤 작품은 깃허브에 잠들어 있고, 어떤 작품은 노션 한 페이지에 갇혀 있다." / 화면은 보여 주고 설명하지 않는다 — 원할 때만 보여 준다(09-23).
- **대비 한 줄(가장 셈):** 깃허브 = 코드의 집 · 노션 = 한 페이지 · 링크트리 = 링크 묶음 · Nookframe = 한 사람의 작품 집.
- **다른 점:** 만들다 만 것·시험용도 전부 괜찮다(낮은 문턱) · 라이브로 만져 보는 포트폴리오(iframe) · 누가 만들었냐보다 뭘 만들었냐가 먼저(작품이 주인공).
- **누구를 위해:** 바이브코더 — AI를 곁에 두고 혼자 만드는 사람(비개발자·학생·직장인 포함). 주 대상은 영어권.
- **방향 (05-21):** 파일 올리기 + 라이브 임베드가 중심이다. 영상 중심으로 돌지 않는다 — 영상은 예고편(퍼뜨리기), 프레임은 극장(머물게 하기).

## 2. 이름

- 제품 이름 **`nookframe` — 어디서나 소문자**(11-06, 로고와 같게. 브랜드에 이만큼 집착한다는 걸 보여 준다). **문장 첫머리도 소문자**(iPhone·eBay처럼) — 이름을 피해 문장을 비틀지 않는다. 남이 쓰는 글의 대문자는 신경 쓰지 않는다. 05-30에 Vibefolio에서 바꿈. 화면 글의 `Nookframe` 212곳·연결 도구 목록 이름은 영어 문구를 모아 고칠 때 같이 바꾼다. 레포·Vercel 이름 `vibefolio`는 일부러 둔다.
- 한국어로 말할 때(채팅·대화) "눅프레임"이라 불러도 된다(11-05). 화면 글의 이름은 그대로.
- 공개 페이지 전체 = **프레임**(영어 frame) · 서비스를 설명하는 문장 = **라이브 포트폴리오**(live portfolio) · 페이지 안 신분 카드만 = **명함**. 페이지 전체를 명함이라 부르지 않는다(사무적이라 버림, 08-10).

## 3. 로고 — 커서 블록 (07-18)

- JetBrains Mono 500 소문자 `nookframe` + 꽉 찬 블록 커서. 블록 `.55em × 1.02em`, 모서리 `.05em`, 왼쪽 띄움 `.08em`.
- **어기면 브랜드가 깨지는 규칙** (네이버 연상 막기):
  1. `n` 혼자 쓰지 않는다 — 가장 작은 단위도 늘 `n` + 블록(아이콘·파비콘·워터마크 전부).
  2. 블록은 늘 글자색이다(currentColor).
  3. 초록 기운 바탕 위에 혼자 두지 않는다.
- 머리글 로고의 블록은 깜빡이지 않는다. 타자를 치는 곳(영상 끝 화면·데모)만 0.95초 `steps(1)`로 깜빡인다.
- 파일: `components/Logo.tsx`(공용 워드마크) · `app/icon.png`(크림 타일) · `app/apple-icon.png`(잉크 꽉 찬 타일) · `app/favicon.ico` · 공유 그림 `public/og/home-{en,ko}.png`(`lib/siteShareImage.ts`, 11-05).
- 원본 비교안: Claude Design 프로젝트 "Nookframe Design System" `previews/logo-b-v2.html`.

## 4. 색 — 종이와 잉크

값은 `app/globals.css` 변수만 쓴다. 다크 모드는 **종이를 어둡게 한 것**이지 뒤집은 것이 아니다(06-03).

| 이름 | 밝음 | 어두움 | 쓰임 |
|---|---|---|---|
| 바탕 `--bg` | `#fdfaf3` | `#1a1612` | 페이지 |
| 영상·공유 그림 종이 | `#f4ede0` | — | 끝 화면·OG·광고 바탕 |
| 잉크 `--text-primary` / `--blue` | `#1a1612` | `#f4ede0` | 글자·진한 버튼·로고 |
| 보조 글 `--text-secondary` | `#6a5e4e` | `#b8a98a` | 부제·주소 |
| 옅은 채움 `--surface-soft` | `#f3ecd9` | `#2a221d` | 칸 나누기(선 대신) |
| 고름 `--surface-active` | `#e3d5ae` | `#3d3229` | 고른 것 |
| 위험 `--danger` | `#b34747` | `#db7a71` | 되돌릴 수 없는 일·실패 |

- 강조색은 따로 없다 — 잉크 하나에 진하기 단계(1.0 / 0.82 / 0.6, 0.6 밑 금지).
- 종이 결(grain)·도장은 `--paper-blend`(밝음 multiply, 어두움 overlay)로 얹는다.
- **종이는 틀, 작품은 창 (11-06):** 종이(바탕·결)는 페이지 바탕·명함 카드·끝 화면·영상의 작품 둘레에만 쓴다. 작품 화면은 원래 색 그대로 — 질감·누런 빛·색 보정을 얹지 않는다(보이는 건 다 진짜, §1).

| 역할 | 글꼴 | 어디 |

| 로고·고정폭·주소 | JetBrains Mono 500 | 워드마크, `nookframe.com`, 끝 화면 타자 |
| 큰 제목(세리프) | Hahmlet (한글은 잘라 만든 서브셋 우선) | 홈 문구·명함 이름 `.vf-serif-display` |

- **사람의 말은 세리프, 사실·주소·기록은 고정폭 (11-06).** 누가 한 말인지를 글꼴이 말해 준다 — 홈 문구·소개 글·이름은 Hahmlet, 주소·날짜·숫자·'누가 언제 확인했나'(확인 도장)는 JetBrains Mono. 본문 Inter는 화면 안내 글.
- 화면엔 위 세 글꼴(Inter·Hahmlet·JetBrains Mono)만 쓴다. 소개 영상(§8)은 장르마다 자기 글꼴을 쓴다.
- 광고·영상 글꼴은 전부 SIL OFL 1.1(상업 광고 가능, 글꼴 파일 판매는 불가).

## 6. 모양

`docs/ui-rules.md` §2가 기준이다. 브랜드로 읽히는 핵심만: 선 대신 옅은 채움 · 진한 버튼은 글자만큼의 알약 · 공개 페이지는 '프레임' 한 장(명함은 명함 카드만) · 단계 표시 아이콘은 같은 굵기의 선 아이콘, 잉크만(로고·초록 배지 섞지 않음) · 미리보기는 진짜와 같은 조각·같은 비율.

## 7. 말투

- 화면 글: 해요체, 짧고 능동적. 버튼 이름 = 누르면 일어날 일. 실패는 사람 말로.
- 홈 문구는 두 묶음이고 **섞지 않는다**:
  - 로그아웃(`lib/taglines.ts`) — 처음 온 사람도 아는 말: 정체성 + 응원 + 자기 비하 유머. 실시간 숫자 `{N}`은 여기만.
  - 로그인(`lib/loggedInTaglines.ts`) — 만드는 사람이 피식하는 개발 밈. 질문·답 `{ text, reply }`는 여기만, 답 앞 표시는 `↳`(사용자가 고름).
  - 영어 묶음(`taglineIntrosEn`·`taglinesEn`)은 번역이 아니라 영어로 새로 쓴다(11-04).
- 꼬리 문장부호를 찍지 않는다(사용자가 그대로 준 줄은 예외). "~하는 사람" 같은 신분 딱지 대신 관찰하는 말("~도 사용 중"). 문구에 '집·공간' 비유는 쓰지 않는다(05-22 — 행동·결과·경험의 말로).
- 바깥 소개 글(소개·공유 설명·발표·게시글)은 로그아웃 묶음의 말투(시처럼, 관찰하듯). SaaS 비교표 같은 그림은 피한다.
- **영상도 같은 선 (11-06):** 홍보 짧은 영상 = 밈(만드는 사람이 피식하는 한 줄), 눅프레임 소개 작품 3편 = 시(관찰하듯, 설명하지 않고).

## 8. 움직임 — 지금 있는 것

- **타자 속도는 어디서나 같다 (09-26):** 한 글자 90 + 0~60ms, 지우기 50 + 0~35ms, 끝난 줄 1.6초 머묾, 줄 사이 420ms, 답 앞 650ms. 한글은 자모 수만큼 친다. 홈·로봇 타자·끝 화면·홍보 영상·광고가 전부 이 속도(`components/TypingTagline.tsx`).
- **커서 깜빡임:** 0.95초 `steps(1)`(부드럽게 사라지지 않고 딱 끊김).
- **작품 촬영 영상 (데모):**
  - 한 번에 찍은 한 장면, 중간 컷 없음(앱 애니메이션이 순간이동처럼 보여서). 본편 약 24초.
  - 카메라 = 커서를 따라 머물며 당기는 확대(1.3~2배). 커서는 누르는 장면에만 보인다. 카메라가 커서를 졸졸 따라다니는 것·스크롤 끌기는 버렸다(08-25).
  - 첫 3초 '미리 보여 주기'(그 영상의 진짜 결과 장면을 먼저) — 정했고 아직 안 만듦(10-04).
  - **작품은 늘 꽉 찬 화면 (11-06):** 브라우저 틀·기기 모양·종이 여백으로 작품을 줄이지 않는다(사용자: 크기 손해가 생각보다 큼). 첫 장면 표시 = **주소 줄이 내려왔다 올라가기** — 영상 종이(`#f4ede0`)색 줄에 고정폭 `nookframe.com/@핸들█`, 맨 위에서 0.1초에 내려와(0.35초) █가 한 번 깜빡(0.95초), 1.25초 머문 뒤 올라간다(0.35초). 올라가는 끝이 미리 보여 주기 3초의 끝과 같은 박자(3.0초). 움직임은 기계 쪽(늘 같은 곡선, 딱 멈춤). 미리 보여 주기는 그 아래서 처음부터 돌아 늦어지지 않는다. 처음(주소 줄)과 끝(주소를 쳐서 `n█`)이 같은 주소로 이어진다. 버린 것: 종이 틀 계속·기기 안·틀에서 들어가기·모서리 n█·오른쪽에서 튀어나오는 n█.
  - 워터마크 = 주인 핸들만.
- **끝 화면:** 마지막 장면을 흐리게 깔고 `nookframe.com/@핸들`을 타자로 친 뒤 `n█`로 끝난다(글자색은 바탕 밝기에 맞춤, 로고 높이 = 화면의 5%).
- **화면 없는 작품의 소개 영상:** 장르 17개(영수증·터미널·LCD·탑승권·카세트·사진부스 등) — 작품마다 다른 장르, 주인의 다른 작품과 안 겹치게. 장르 사이에 공통인 건 마지막 약 2초의 `nookframe.com/@핸들` 넘겨주기뿐(그 장르의 잉크·글꼴로, 작게).
- **홍보 짧은 영상:** 밈 한 줄 타자 + 로고 끝 화면, 소리 없음, 영상 안에서 서비스 설명 안 함("로고를 보여 주는 데서 끝").

## 9. 캐릭터·광고 (광고 v1, 09-27)

- **주인공 = 커서 블록 캐릭터:** 잉크 세로 블록 + 흰 눈 + 짧은 발.
- **결:** 손그림 2D — 살짝 떨리는 굵은 선, 선에서 어긋난 색칠, 빗금 볼터치, 베이지 종이 질감 + 어두운 모서리, 옅은 배경에 캐릭터만 진하게. 컷 없이 카메라가 천천히 다가간다.
- **그리는 과정을 보여 주는 장치:** 스케치(회색 겹선) → 잉크 → 색칠이 겹쳐 흐른다("실제로 그리는 것처럼"), 한꺼번에 바뀌지 않는다.
- **글:** "만든다는 것, / 그것만으로 대단한 일" → "만든 다음에는?" → 타자로 "이제 보여줄 시간." → `nookframe.com` → `n█`. 대사·설명 문구 없음.
- 세로 영상은 아래 약 30%를 비운다(릴스·쇼츠 자막·버튼 자리).
- 다음 광고(나중): '보여주기' — 감정을 움직이는 광고(어릴 때 만든 걸 보여 주던 기억 같은 것).

## 10. 소리

- **소리 = 타자 소리만 (11-05):** 우리가 직접 합성해 만든 키 소리를 글자 하나에 한 번씩, 타자 속도(§8)에 정확히 맞춘다. 음악은 넣지 않는다. 공개 소리(CC0)는 남도 같은 소리를 쓸 수 있어 브랜드 소리로 쓰지 않는다.
  - 타자 소리는 '사람 쪽'이라 간격이 들쭉날쭉한 그대로 둔다. 마지막 `n█`가 뜰 때만 다른 소리 하나 — 늘 같은 소리, 같은 크기(소리 로고).
  - **정한 소리 (11-06):** 키 = **볼펜 딸깍 가족 5개**(원본 + 아주 가까운 형제 4) — 누를 때마다 번갈아, 높이 ±4%·세기 80~100%로 조금씩 흔든다. 끝 = **필름 카메라 셔터** 한 번 — `n█`가 한 번 깜빡인 뒤 고정되는 순간(끝 화면 `local-runner/endcap.ts`의 착지 + 0.95초). "프레임을 찍는" 소리.
  - 파일·만든 과정: `~/Desktop/nookframe-작업물/brand-sound/`(README에 모델·주문·seed·고른 과정 — 사람이 고르고 다듬은 기록). Stable Audio 3 small-sfx 정식판, Stability AI Community License 등록(11-06, 연 매출 $1M 미만 무료). 영상에 소리만 쓰면 출처 표시 필요 없음.
  - 소리를 끈 채로 봐도 똑같이 읽혀야 한다(피드는 무음으로 시작한다).
  - 이미 나간 광고 v1·홍보 짧은 영상은 무음 그대로 둔다.
- 옛 '합성음 금지'(09-27)는 광고 v1에서 그리는 단계마다 붙인 합성 효과음이 별로였던 데서 나온 것 — 11-05에 풀었다. 배운 것은 남긴다: 동작마다 소리를 붙이면 과하고, 삑 하는 전자음 티가 나면 싸 보인다.

## 11. 빈 칸 — 아직 안 정한 것 (11-05)

- **움직임 언어 — 첫 줄은 정함 (11-05):** "사람이 한 일은 흔들리게, 시스템이 한 일은 정확하게."
  - 사람 쪽(흔들림): 타자, 커서 움직임, 손그림 선, 작품 화면.
  - 기계 쪽(정확함): 커서 깜빡임, **카메라**, **장면 전환**, 확인 도장, 끝 로고. 카메라는 '확인하는 로봇의 눈' — 손떨림 없이 매번 같은 곡선으로 다가가고, 멈출 땐 딱 멈춘다. 장면 전환은 깜빡임 박자(0.95초)에 맞춰 딱 바뀐다.
  - 화면 틀·첫 장면 표시는 정함(11-06, §8). 아직 빈 것: 글자가 나타나는 방식, 컷 길이.
- **이미지 규칙:** 사진·그림·작품 화면을 브랜드 안에서 어떻게 보여 주나.
- **영어 말투 기준 (11-06 진행 중):**
  - 누가 말하나 = 자리로 나눈다: 약속·정책·실패 안내는 **We**, 홈 문구·소개 글은 **주어 없이**, 버튼은 **동사만**. 줄임말(don't) 쓴다. 상대는 늘 **you**.
  - **길이 상한(단어 수, 11-06):** 홈 문구·소개 줄 ≤ 9 · 로그인 홈 밈 ≤ 12(답 줄 ↳은 따로) · 홍보 짧은 영상 ≤ 8 · 소개 작품 장면당 ≤ 7 · 버튼 1~3 · 제목 ≤ 6 · 안내·실패 글 한 문장 ≤ 15, 최대 두 문장 · AI에게 보이는 오류 설명은 상한 없음(정확한 게 먼저). 까닭: 홈 문구는 타자로 쳐진다(9단어 ≈ 5.7초).
  - **반쪽 문장(주어·동사 없는 문장, 11-06):** 밖에 보이는 말(홈 문구·홍보 짧은 영상·소개 작품·공유 설명)에서만. 화면 안내·실패·약속·메일은 온전한 문장 — '누가 말하나'에서 주어 없이 말하는 자리와 같게 갈린다.
  - 아직: 문장 모양 2(끝 마침표·줄표·말줄임표·대문자 방식) · 쓰지 않는 낱말 · 유머 세기 · 작품 부르는 말·날짜 형식·철자. 다섯 가지를 다 얘기한 뒤 지금 있는 영어 문구를 모아 고친다.
- 벤치마크 조사(폴스타 + 브랜딩에 집착하는 소프트웨어 회사)를 바탕으로 이 칸을 채운다.
